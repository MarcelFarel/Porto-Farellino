Grocery Basket Analysis

End-to-End Data Engineering Lifecycle

Raw data from SuperMarket Analysis.csv is extracted, cleaned, standardized, and loaded through modular Pentaho transformation files. Orchestration.kjb chains them so every dimension exists before the fact table looks up its keys.

Source and staging

SuperMarket Analysis.csv

1,000 rows, 17 columns

MySQL staging table

Job order in Orchestration.kjbStart to Success

  1. 1

    LocationDimension.ktr

    Table input, then Combination lookup/update on branch + city, returning location_id.

  2. 2

    ProductDimension.ktr

    Combination lookup/update on product_line, returning product_id.

  3. 3

    CustomerDimension.ktr

    Combination lookup/update on customer_type + gender, returning customer_id.

  4. 4

    TimeDimension.ktr

    Parses text dates with STR_TO_DATE(Date, '%m/%d/%Y'), derives day, month, year, day name, and quarter, drops repeats with Unique rows (HashSet), then writes the table.

  5. 5

    SalesFact.ktr

    Reads a high-water mark from the warehouse, pulls newer staging rows, resolves four surrogate keys with Database lookup steps, and writes SalesFact.

Incremental load inside SalesFact.ktr

Two Table input steps. The first reads the latest loaded date, the second passes it in as the parameter.

-- Table input 2 (olap): latest date already in the warehouse
SELECT IFNULL(MAX(Date), '1900-01-01') AS latest_date
FROM olap.salesfact sf
JOIN olap.timedimension td ON sf.time_id = td.time_id;

-- Table input (oltp): staging rows newer than that date
SELECT invoice_id, branch, city, customer_type, gender, product_line,
       unit_price, quantity, tax_five_percent, sales,
       STR_TO_DATE(Date, '%m/%d/%Y') AS date_formatted,
       Time, payment, cogs, gross_margin_percentage, gross_income, rating
FROM oltp.supermarket_sales
WHERE DATE > ?;

Data quality check on the warehouse load

Reconciling the warehouse against the source showed that repeated job runs had left 3,380 rows in SalesFact for 1,000 distinct invoices. The incremental filter compares the raw text Date column instead of the parsed date, so the high-water mark does not reliably skip rows that are already loaded. ProductDimension also holds a stray row containing the CSV header text Product line.

Next iteration: filter on STR_TO_DATE(Date, '%m/%d/%Y') > ?, add a unique key on invoice_id, and skip the header row during staging. The figures above come from the 1,000-row source.

Trained a Scikit-Learn LinearRegression model that maps rainfall intensity (rainFall_mm) and rain duration (rainDuration_minutes) to a base flood depth in centimeters, then scales it by a localized administrative-zone factor. Integrated jakarta_geo.json with Plotly Express to render interactive district-level risk maps across Central, North, West, South, and East Jakarta.

Prediction logic
