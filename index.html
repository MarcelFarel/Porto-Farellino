Raw data from SuperMarket Analysis.csv is staged in MySQL (oltp.supermarket_sales) and loaded into the olap warehouse through five sequential Pentaho Kettle transformations orchestrated by Orchestration.kjb. Select any step below to inspect its exact Kettle implementation.

Step 1: LocationDimension.ktr

Reads SELECT branch, city FROM oltp.supermarket_sales and runs a Kettle Combination lookup/update step against olap.LocationDimension to issue surrogate keys location_id 1 to 3 (Alex/Yangon, Giza/Naypyitaw, Cairo/Mandalay).

Step 2: ProductDimension.ktr

Selects product_line from staging and runs Combination lookup/update to populate olap.ProductDimension with surrogate keys product_id for all six supermarket categories.

Step 3: CustomerDimension.ktr

Extracts customer_type and gender from staging and resolves the 4 distinct combinations (Member/Female, Member/Male, Normal/Female, Normal/Male) into customer_id 1 to 4.

Step 4: TimeDimension.ktr

Parses string dates with STR_TO_DATE(Date, '%m/%d/%Y'), extracts day, month, year, day_name, and quarter, deduplicates the stream with a Kettle Unique rows (HashSet) step, and writes 89 unique dates into olap.TimeDimension.

Step 5: SalesFact.ktr

Queries the latest loaded date from the warehouse, reads staging transactions, chains four Database lookup steps to attach location_id, product_id, customer_id, and time_id, and outputs the rows into olap.SalesFact.

High-water mark SQL inside SalesFact.ktr

-- Table input 2 (olap): get latest loaded timestamp
SELECT IFNULL(MAX(Date), '1900-01-01') AS latest_date
FROM olap.salesfact sf
JOIN olap.timedimension td ON sf.time_id = td.time_id;

-- Table input (oltp): pull staging rows
SELECT invoice_id, branch, city, customer_type, gender,
       product_line, unit_price, quantity, tax_five_percent,
       sales, STR_TO_DATE(Date, '%m/%d/%Y') AS date_formatted,
       Time, payment, cogs, gross_margin_percentage,
       gross_income, rating
FROM oltp.supermarket_sales
WHERE DATE > ?;

Warehouse data quality audit (idempotent reload fix)

Reconciling olap.sql against SuperMarket Analysis.csv revealed why the raw dump reported $1.08M to $1.29M across 3,380 fact rows when the 1,000 source invoices sum to $322,966.75:

  • In SalesFact.ktr, WHERE DATE > ? compares the unparsed M/D/YYYY string column in staging against the ISO timestamp parameter, allowing repeated job runs to re-insert existing invoices.
  • ProductDimension contained a 7th row (product_id = 7, 'Product line') from an unskipped CSV header row.
  • Fix applied in this dashboard: filter on STR_TO_DATE(Date, '%m/%d/%Y') > ?, enforce UNIQUE KEY (invoice_id) on SalesFact, and enable header skipping during CSV staging.

Data cleaning & feature engineering

Processed raw Indonesian government flood records (dataset_banjirJakarta.csv). Removed hundreds of recording anomalies in the precipitation variable, standardized administrative strings (kota_administrasi, kecamatan, kelurahan, rw), and engineered the target waterLevel_cm feature by averaging minimum and maximum recorded flood depths. 

# Target feature engineered in Main.py
df['waterLevel_cm'] = (
    df['ketinggian_air_min_cm'] + df['ketinggian_air_max_cm']
) / 2

# Strip whitespace on administrative strings
df.columns = df.columns.str.strip()
df['kota_administrasi'] = df['kota_administrasi'].str.strip()

Regression & RW zone weighting (Main.py)

Fits LinearRegression on rainfall intensity and duration, then weights the base prediction by the ratio of the selected RW's historical mean flood depth to the Jakarta-wide mean, clamped between 0.8 and 1.5. 

X = df[['rainFall_mm', 'rainDuration_minutes']]
y = df['waterLevel_cm']
model = LinearRegression()
model.fit(X, y)

pred_base = max(0, model.predict([[rain, dur]])[0])
avg_jakarta = df['waterLevel_cm'].mean()
factor_rw = (avg_flood_rw / avg_jakarta) if avg_jakarta > 0 else 1.0
factor_rw = max(0.8, min(factor_rw, 1.5))
final_pred_rw = pred_base * factor_rw

Client-side validation rules (Register.js)

const validator = {
  rules: {
    username: v => !v.trim() ? 'Username required' :
                   v.length < 3 ? 'Min 3 characters' :
                   v.length > 20 ? 'Max 20 characters' : null,
    email: v => !v.trim() ? 'Email required' :
                !v.includes('@') || !v.split('@')[1]?.includes('.')
                ? 'Invalid email' : null,
    phone: v => {
      const digits = v.replace(/\D/g, '');
      return !digits ? 'Phone required' :
             digits.length < 8 ? 'Min 8 digits' :
             digits.length > 15 ? 'Max 15 digits' : null;
    },
    password: v => !v ? 'Password required' :
                   v.length < 8 ? 'Min 8 characters' :
                   !/[A-Z]/.test(v) ? 'Need uppercase' :
                   !/[a-z]/.test(v) ? 'Need lowercase' :
                   !/\d/.test(v) ? 'Need number' : null
  }
};
